# Adding a Generator to rakitin

> Tutorial for rakitin v3. Everything below matches the current APIs:
> `lib/safety.js`, `lib/naming.js`, `lib/deps/manifest.js`,
> `lib/template/engine.js`, `lib/commands/{shared,add}.js`, `bin/rakitin.js`
> and the Jest harness in `tests/setup.js`.
>
> Worked example: a new headless generator used as
> `rakitin add service audit-log --json`.
>
> Shipping an out-of-tree generator instead? See
> [plugin-authoring.md](./plugin-authoring.md) — the plugin API v1 gives you
> the same `{created, skipped}` contract, `ctx.safety`, `ctx.naming` and
> `registerKind`, without touching this repository.

---

## 0. Design decisions before you type

Generators are **headless-first**: the core function works purely from
arguments, because CI runs, `--json` agents and `--yes` unattended mode all
depend on it. Prompts belong to the command layer, and only when the caller
did not supply the value and `--yes` is absent.

| Question | Convention |
| --- | --- |
| Where does output go? | Conventional locations from `getPaths(root)` (`app/shared`, `app/modules/<kebab>/…`). Never guess from `process.cwd()`. |
| Does the output need npm packages? | Register a kind in `KIND_DEPENDENCIES` (§4). Never install inline. |
| Interactive behavior | The core takes everything as parameters; the command layer prompts only to fill gaps. |
| Overwrite policy | Route every write through the safety layer; write-if-absent by default, `.bak` when re-writing. |
| Return shape | `{ created: string[], skipped: string[], data? }` with **root-relative POSIX** paths. |

## 1. Build the non-interactive core

Create `lib/generator/service/service.js`. Requirements:

- Plain-data signature, no prompting.
- Paths resolved lazily via `getPaths(root)` **at call time**.
- Names derived from `lib/naming.js` (`assertSafeName`, `getModuleVariants`,
  `toIdentifier`) — never hand-rolled case conversion.
- Returns `{ created, skipped, data }` with root-relative POSIX paths.

```js
// lib/generator/service/service.js
const path = require("path");
const { getPaths } = require("../../constants");
const { assertSafeName, getModuleVariants } = require("../../naming");
const { writeFileIfNotExistsSafe, writeOutcome } = require("../../safety");
const { relativePosix } = require("../../utils");
const { defaultEngine } = require("../../template/engine");

const TEMPLATE = path.join(__dirname, "..", "..", "templates", "service", "service.ejs");

/**
 * Generate a shared service at app/shared/services/<kebab>.service.js.
 * @param {string} name Raw service name ("audit log", "AuditLog", …).
 * @param {{root?: string}} [options]
 * @returns {Promise<{created: string[], skipped: string[], data: object}>}
 */
async function createService(name, options = {}) {
  const root = options.root || process.cwd();
  const kebab = assertSafeName("module", name);           // reuse the module guard
  const variants = getModuleVariants(kebab);

  const filePath = path.join(getPaths(root).sharedPath, "services", `${kebab}.service.js`);
  const content = defaultEngine.renderFile(TEMPLATE, {
    pascal: variants.pascal,                              // safe identifier
    camel: variants.camel,
  });

  const verdict = writeFileIfNotExistsSafe(filePath, content);
  const bucket = { created: [], skipped: [] };
  bucket[writeOutcome(verdict)].push(relativePosix(root, filePath));

  return { ...bucket, data: { name: kebab, file: relativePosix(root, filePath) } };
}

module.exports = { createService };
```

And `lib/templates/service/service.ejs`:

```ejs
// <%= pascal %> Service - generated by rakitin

class <%= pascal %>Service {
  constructor() {
    this.items = [];
  }

  async getAll() {
    return this.items;
  }
}

module.exports = new <%= pascal %>Service();
```

Why this shape works downstream: `printResult` consumes `created`/`skipped`
directly; `--dry-run` and `--overwrite` come for free because the write went
through the safety layer; and the returned `data` documents intent without
hidden side effects.

## 2. Route every write through the safety layer

```js
const {
  writeFileIfNotExistsSafe,
  overwriteWithBackup,
  updateJsonFile,
  mergeEnvExample,
  buildMarkedBlock,
} = require("../../safety");
```

| Helper | On disk | Under `--dry-run` | Under `--overwrite` |
| --- | --- | --- | --- |
| `writeFileIfNotExistsSafe(filePath, content)` | creates parents, writes only when absent; `{written, skipped: "exists"\|null}` | records `{op:"create", path}` | re-writes through `overwriteWithBackup` (`.bak` kept) |
| `overwriteWithBackup(filePath, content)` | copies the previous bytes to `<file>.bak` (then `.bak.1`, …), then writes | records `{op:"overwrite", path, backup}` | same |
| `updateJsonFile(filePath, mutator)` | parse → mutate → re-serialize + `.bak`; `mutator` returning `false` = "unchanged" | records the write | same |
| `mergeEnvExample(root, marker, content)` | appends a `# <MARKER>` section at most once | records the write | same |

Never call bare `fs.writeFileSync` against user-project files from a
generator: it bypasses `--dry-run`, skips backups, and breaks the
non-destructive guarantee `doctor` advertises. For directory creation use
`utils.ensureDir` (plan-aware) rather than `fs.mkdirSync`.

For managed regions (main router, module router resource block, GraphQL SDL,
WebSocket registry) do not hand-assemble strings — use
`buildMarkedBlock({existing, startToken, endToken, inner, header,
eofFallback, commentPrefix})` and the exported token constants, so bytes
outside the region are preserved exactly.

## 3. Use the EJS template engine

Templates live under `lib/templates/<area>/*.ejs` and are rendered with the
shared engine:

```js
const { defaultEngine } = require("../../template/engine");
const out = defaultEngine.renderFile(absTemplatePath, locals);
```

Rules:

1. Every dynamic value arrives as a local — templates never read
   `process.env` or the filesystem.
2. Any identifier interpolated into generated JS must come from
   `toIdentifier()` / `getModuleVariants().identifier` **in the generator**,
   passed as a ready-to-use local (`pascal`, `camel`, …). Never interpolate
   raw user input into code.
3. Use `<%= %>` for escaped text and `<%- %>` for raw output; `include()`
   resolves relative to the template because `renderFile` bakes the absolute
   `filename` into the compiled function.
4. Template filenames are kebab-case; partials live beside their consumers.
5. Prefer rendering one template with a `verbs`-style local over duplicating
   a template per variant (this is how `--template crud|readonly|graphql|
   realtime` is implemented — see `lib/generator/module/verbs.js`).

## 4. Register dependencies in `KIND_DEPENDENCIES`

If your output imports packages the project may not have, declare them in
`lib/deps/manifest.js`:

```diff
--- a/lib/deps/manifest.js
+++ b/lib/deps/manifest.js
@@
   "middleware:auth": ["jsonwebtoken"],
+  // Service family (rakitin add service ...)
+  "service:core": [],
+  "service:prisma": ["@prisma/client", "prisma", "dotenv"],
+  "service:mongoose": ["mongoose"],
```

That single registration makes several things true automatically:

1. `resolvePackagesForKinds(["service:prisma", "module:prisma"])` dedupes
   across kinds, so packages install **once** per run.
2. `ensureDependencies(kinds, {pm, install, dev, silent, extraKinds, root})`
   installs only what is missing, with the detected or explicit package
   manager, and no-ops under `--no-install`/`--dry-run`.
3. An unknown kind is a **hard error**
   (`Kind dependency tidak dikenal: "<kind>"`), never a silent skip — that is
   how dangling imports were eliminated.

Kinds whose packages belong in devDependencies must be added to `DEV_KINDS`
(see `test:dev`).

## 5. Wire it into the CLI

### 5a. Command layer — `lib/commands/add.js`

Add a `case` to `addCommand`'s switch plus a thin adapter that fills prompts
only when allowed and calls `ensureDependencies` exactly once:

```js
// lib/commands/add.js (excerpt)
const { createService } = require("../generator/service/service");
const { ensureDependencies } = require("../deps/manifest");
const { runWithPluginInstall } = require("./shared");

async function addCommand(thing, name, context = {}) {
  switch (thing) {
    case "module":
      return addModule(name, context);
+   case "service":
+     return addService(name, context);
    // …
  }
}

async function addService(name, context = {}) {
  let serviceName = name || context.name || null;
  if (!serviceName && !context.yes) {
    const answers = await inquirer.default.prompt([
      { type: "input", name: "serviceName", message: "Nama service:" },
    ]);
    serviceName = answers.serviceName;
  }
  if (!serviceName) throw new Error("Nama service wajib ada. Contoh: rakitin add service audit-log --yes");

  const result = await createService(serviceName, { root: context.root });

  const installResult = await runWithPluginInstall(context, () =>
    ensureDependencies(["service:core"], {
      pm: context.pm,
      install: context.install,
      extraKinds: pluginExtraKinds(context),
      silent: true,
      root: context.root,
    })
  );

  return {
    ok: true,
    created: result.created,
    skipped: result.skipped,
    nextSteps: [`Impor service: require('./app/shared/services/${result.data.name}.service')`],
    data: { ...result.data, install: installResult },
  };
}
```

Note the `runWithPluginInstall` wrapper: it fires the `preInstall`/
`postInstall` plugin hooks around the install, exactly like the core
commands do.

### 5b. Bin dispatcher — `bin/rakitin.js`

Declare the flags your generator needs on the `add` command and add the thing
to the `ADD_THINGS` list so yargs documents it:

```js
const ADD_THINGS = ["module", "middleware", "util", "config", "endpoint",
  "validation", "docs", "test", "graphql", "websocket" /* , "service" */];
```

The `add <thing> [name]` declaration routes through `run(argv, …)`, which
already provides the shared prelude: `buildContext` (flag normalization),
`enterProjectRoot` (single `--cwd` chdir), `enableJsonMode()` for `--json`,
`beginPlan()` for `--dry-run`, `setOverwrite()` for `--overwrite`, and the
plan merged into `printResult`.

### 5c. Catalog

`rakitin list` derives its catalog from the live registries
(`lib/commands/list.js`): add your kind to the relevant registry
(`MIDDLEWARE_KINDS`, `CONFIG_KINDS`, `UTIL_KINDS`, `TEMPLATES`, an
`.arch.js` file, a recipe entry in `RECIPES`, or a docs/manifest kind) and it
appears automatically. If your family is not registry-driven, add an explicit
entry in `buildCatalog()`.

## 6. Declare env keys

When the output reads configuration from `.env`, never write `.env` and never
clobber `.env.example`. Use `mergeEnvExample`:

```js
const { mergeEnvExample } = require("../../safety");

const SERVICE_ENV = `SERVICE_MAX_ITEMS=100
SERVICE_TTL_SECONDS=300`;

const verdict = mergeEnvExample(root, "SERVICE CONFIG", SERVICE_ENV);
// -> { written, skipped: "marker-exists"|null, path }
```

The marker makes it idempotent: a second run with the same marker is a no-op
reported in `skipped[]`. Keep the env constant next to the template that
consumes it.

## 7. `nextSteps`

Every result ends with an actionable `🧭 Next steps` block rendered by
`printResult`. Guidelines:

- Make each step copy-pasteable (a real command or a real import path).
- Put the step that verifies/uses the output first.
- Numbers come free (`1. 2. 3.`).

Calibrate against `buildModuleNextSteps()` in `lib/commands/add.js` and the
recipe `nextSteps` arrays in `lib/commands/recipe.js`.

## 8. Tests (hard gates)

A generator is complete only with the three assertions below. Put them in a
dedicated suite (`tests/lib/generator/service.test.js`) and/or a policy gate
under `tests/regression/`. Use the real fs sandbox: `tests/setup.js` gives
each suite a private `global.tempDir` with `process.cwd` pointed at it, and
blocks child processes.

```js
const fs = require("fs");
const path = require("path");
const vm = require("vm");
const safety = require("../../lib/safety");
const { createService } = require("../../lib/generator/service/service");

describe("createService", () => {
  afterEach(() => safety.resetPlan());

  test("generated artifact compiles (codegen gate)", async () => {
    const r = await createService("audit log", { root: global.tempDir });
    const file = path.join(global.tempDir, r.created[0]);
    expect(fs.existsSync(file)).toBe(true);
    expect(() => new vm.Script(fs.readFileSync(file, "utf8"))).not.toThrow();
  });

  test("dry-run records the intent and touches nothing", async () => {
    safety.beginPlan();
    try {
      const r = await createService("pricing", { root: global.tempDir });
      expect(r.created).toEqual(["app/shared/services/pricing.service.js"]);
      expect(safety.getPlan()).toEqual([
        {
          op: "create",
          path: path.join(global.tempDir, "app", "shared", "services", "pricing.service.js"),
        },
      ]);
      expect(fs.existsSync(path.join(global.tempDir, "app"))).toBe(false);
    } finally {
      safety.resetPlan();
    }
  });

  test("idempotent: second run skips, first content survives", async () => {
    const first = await createService("billing", { root: global.tempDir });
    expect(first.created).toEqual(["app/shared/services/billing.service.js"]);

    const second = await createService("billing", { root: global.tempDir });
    expect(second.created).toEqual([]);
    expect(second.skipped).toEqual(["app/shared/services/billing.service.js"]);
    expect(
      fs.readFileSync(path.join(global.tempDir, second.skipped[0]), "utf8")
    ).toContain("class BillingService");
  });
});
```

Why each gate exists:

- **`vm.Script` compile check** — catches syntax regressions in templates.
  Fragments that reference user-project modules may strip/substitute
  `require(...)` first, but the syntax must still be gated.
- **dry-run plan assertion** — proves the write went through the safety layer
  (a bare `writeFileSync` would either touch disk or record nothing).
- **idempotency assertion** — guards the write-if-absent contract.

Run it with `npx jest tests/lib/generator/service.test.js`. The full suite
(`npm test`) must leave the git tree clean — the repo-integrity guard in
`tests/setup.js` fails the run otherwise.
